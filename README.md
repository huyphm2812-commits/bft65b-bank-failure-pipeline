# A Big-Data Pipeline for Bank Failure Early Warning

This repository contains the complete, production-grade big-data analytics pipeline for bank failure early warning using public FDIC data (1984Q1–2026Q2). The architecture bridges financial econometrics (CAMELS rating framework, survival hazard modeling, cost-sensitive threshold selection) with large-scale distributed computing (Parquet column storage, Polars lazy execution, and PySpark Catalyst physical plans).

---

## Environment & Prerequisites

* **Tested Python Version:** `Python 3.11.9` (pinned in `.python-version`). Compatible with Python 3.10+.
* **Operating Systems:** Windows 10/11 (PowerShell), Linux, macOS.
* **Java Dependency for PySpark:** Apache Spark requires Java Runtime Environment (JRE/JDK 8, 11, or 17). If not already installed, download [Eclipse Temurin OpenJDK 17](https://adoptium.net/temurin/releases/).

## Full Run (Ordered Production Pipeline)

Execution on historical FDIC data (1984Q1–2026Q2, ~1.68M bank-quarter observations):

```powershell
# 1. Connection Probe (10 seconds)
python scripts\run_pipeline.py connection

# 2. Historical Acquisition & Raw Archiving (~45-60 minutes)
# Resumable across chunks; safe to interrupt and restart
python scripts\run_pipeline.py acquire

# 3. Dataset Validation & Manifest Verification (1 minute)
python scripts\run_pipeline.py validate

# 4. Non-Destructive Quality Audit (2 minutes)
python scripts\run_pipeline.py audit

# 5. Bank-Quarter Panel Construction & Labeling (2 minutes)
python scripts\run_pipeline.py panel

# 6. Storage Formats & Compression Benchmark (3-5 minutes)
python scripts\run_pipeline.py benchmark --repetitions 5

# 7. Processing Engine Comparison: Pandas vs Polars LazyFrame (2 minutes)
python scripts\run_pipeline.py engines --repetitions 5

# 8. PySpark Distributed Execution & Catalyst Plan Capture (2-3 minutes)
python scripts\run_pipeline.py spark --repetitions 2

# 9. CAMELS Feature Engineering & Comprehensive Development Analysis
python scripts\run_pipeline.py model --dev-only --dev-analysis --spark-mllib

# 10. Audit Repository Hygiene & Freeze Run Manifest
python scripts\run_pipeline.py check
```

Or execute the complete development chain in a single automated runner:
```powershell
.\scripts\run_full.ps1
```

### Pre-Test Configuration Freeze & Held-Out Test Evaluation

Before evaluating the held-out test split (2008–2014 GFC), configuration parameters must be explicitly frozen without default fallbacks:

```powershell
# 1. Freeze Configuration (requires explicit arguments, supports --dry-run)
python scripts\freeze_config.py `
  --split-train-end 1992-12-31 `
  --split-dev-start 1993-03-31 `
  --split-dev-end 2005-12-31 `
  --split-test-start 2008-01-01 `
  --split-test-end 2014-12-31 `
  --loss-definition DEF_A `
  --fn-fp-ratio 100:1 `
  --feature-variant variant_3 `
  --final-model random_forest `
  --training-policy train_only `
  --seed 42 `
  --threshold 0.103990 `
  --output results_snapshot/07_features_models/frozen_model_config.json

# 2. Rehearsal Run (Validates identical output file inventory on pre-2006 data without real test lock)
python scripts\run_pipeline.py model --rehearsal

# 3. Single Held-Out Test Evaluation (One-Time Execution Gate Enforcing Frozen Config)
python scripts\run_pipeline.py model --config config\config.yaml --frozen-config results_snapshot\07_features_models\frozen_model_config.json --evaluate-test
```
*Note: The `--evaluate-test` command writes a cryptographic lock file `p7_test_evaluation.lock`. It can be run only once to strictly prevent out-of-sample data snooping.*

## Data Architecture & Medallion Stage Map

The pipeline follows the Lakehouse Medallion Architecture across isolated local workspace tiers:

| Medallion Tier | Workspace Directory | Content & Quality Guarantees |
| :--- | :--- | :--- |
| **Bronze (Raw)** | `02_local_workspace/data/raw/` | Immutable, raw FDIC API page payloads (`.json.gz`), chunked with cryptographic SHA-256 manifests. |
| **Silver (Processed)** | `02_local_workspace/data/processed/` | Schema-enforced, year-partitioned Snappy Parquet tables with explicit `timestamp[ms]` keys; non-destructive data quality audit (`outlier_iqr_by_quarter.csv`, zero-variance flags). |
| **Gold (Analytical & Models)** | `02_local_workspace/outputs/` | Curated bank-quarter panel (`03_panel/`), leak-free CAMELS feature matrices and expanding-window tuned models (`07_features_models/`), frozen configs, and reproducible manifests (`08_reproducibility/`). |
